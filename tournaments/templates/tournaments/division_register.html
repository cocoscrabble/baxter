{% comment %} One "add" form for all three ways in, because from the director's side they are one act: search for a name, and take whoever comes back. The results say which list each hit came from, and the button on the row does the rest. There is exactly one registration fieldset on the page now. It used to be rendered twice — once for existing players, once for guests — which meant prefixing the guest copy so the two did not share element ids. One form, no prefix. **This is a registration desk, so it is laid out tight.** The global rule is `label { display: block }`, which puts every field on two lines and pushed the "add as guest" row below the fold on a laptop. `.register-form` overrides that within this form only: each row is a flex line of label + control + help, so the whole thing fits between the search box and the entrant list. The prose that used to explain the three outcomes is gone with it. The headings say which list each result came from and the buttons say what pressing them does ("Enter" / "Enter as guest"), which is the same explanation without costing nine lines every time the page is opened. The rating box is deliberately blank by default: blank means "use the player's own rating", a typed value means the director is overriding it. For a guest nobody has a rating for, that box *is* their rating — which is what its help text says, in the one place somebody filling it in is looking. {% endcomment %}
