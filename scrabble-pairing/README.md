# scrabble-pairing

A standalone pairing engine for Scrabble tournaments.

`scrabble-pairing` is a *stateless* engine for pairing Scrabble tournaments. It provides a single `pair()` function, which takes in the complete state of a tournament, and returns pairings for the next round or rounds.

## Usage

```rust
use scrabble_pairing::{pair, pair_json, PairingInput};

// Typed:
let input: PairingInput = serde_json::from_str(json)?;
let rounds = pair(&input);

// Or straight from/to JSON (the language-agnostic boundary):
let out_json: String = pair_json(json)?;
```

### Input

```jsonc
{
  "players":        [{"name": "Alice", "rating": 1800}],
  "result_slips":   [{"round": 1, "winner_name": "Alice", "loser_name": "Bob",
                      "winner_score": 450, "loser_score": 400, "winner_started": true}],
  "round_pairings": [{"round": 1, "start_round": 0, "pairing": "Swiss"}],
  "fixed_pairings": {"2": [["Alice", "Bob"]]},   // round -> forced pairs (optional)
  "seed": 12345                                   // for the random strategies (optional)
}
```

`pairing` strings are: `KotH`, `QotH`, `Swiss`, `RoundRobin`, `DoubleRoundRobin`,
`Random`, `RandomNoRepeats`, `Quads_Clustered`, `Quads_Distributed`,
`Quads_Equalized`, `Sixes`, `Charlottesville`, `SwissPlusRandom`.

### Output

```jsonc
[{"round": 1, "pairings": [{"first": "Alice", "second": "Bob", "repeats": 0}], "error": null}]
```

`first` is the player who starts; `repeats` is how many times the two have met.
An odd field gets a synthetic `"Bye"` opponent.

Each round carries an `error` field. On an invalid condition — an unknown
strategy string, or a field too small for the chosen format (e.g. quads with
fewer than three players) — that round comes back with empty `pairings` and the
reason in `error`:

```jsonc
[{"round": 1, "pairings": [], "error": "field too small for quads"}]
```

## Determinism

The engine is a pure function of its input. Randomness (for `Random`,
`RandomNoRepeats`, and the random half of `SwissPlusRandom`) comes only from the
caller-supplied `seed` via a seeded ChaCha RNG, not OS entropy. This keeps
runs reproducible and the crate wasm-clean.

## Parity with the Python engine

`tests/parity.rs` checks the engine against the original Python implementation
(the oracle). The corpus is generated by
[`scripts/export_pairing_corpus.py`](../scripts/export_pairing_corpus.py):

```sh
uv run python scripts/export_pairing_corpus.py   # regenerates tests/corpus/cases.json
cargo test                                        # runs unit + parity tests
```

Deterministic strategies must reproduce the oracle output exactly. The only
accepted difference is **within-pair orientation / pairing order for
blossom-matched strategies on start-balancing ties**, which is
implementation-defined (networkx vs. the vendored matching) and semantically
arbitrary; the who-plays-whom set and repeat counts still match exactly. Random
strategies are validated by invariants (everyone paired once, valid opponents,
positive repeat counts).

## Maximum-weight matching

Swiss and the no-repeats strategies use maximum-weight general-graph matching.
That algorithm is vendored from [rustworkx-core](https://github.com/Qiskit/rustworkx)
under `src/vendor/` (a networkx port) rather than taken as a crate dependency,
because `rustworkx-core` unconditionally pulls in `rayon`/`getrandom`, which do
not compile to `wasm32-unknown-unknown`. See [`ATTRIBUTION.md`](ATTRIBUTION.md).

## Portability

The crate builds for `wasm32-unknown-unknown` today (no threads, filesystem,
time, or OS entropy in the core):

```sh
cargo build --target wasm32-unknown-unknown
```

Bindings for other languages are designed as thin, optional-feature wrappers
around `pair_json` (a `pyo3` binding for Baxter, a `wasm-bindgen` binding for the
browser). Neither is built yet.
